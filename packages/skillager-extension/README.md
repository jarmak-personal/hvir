# Skillager extension

An ordinary hvir extension for Your library, skills observed in the current registered project, and closable current-instruction readers. It consumes only the public guest bridge, presentation kit and Skillager CLI contracts. Browsing and refreshing request metadata; clicking a row explicitly reads that occurrence's current `SKILL.md`. Reading pending or blocked content never accepts or executes it. Stub, Router, Full, project original and library occurrences stay distinct. A separately selected canonical jump requires public library UUID and skill identity.

## Build and install

From the hvir checkout, run `npm ci` and `npm run extension:skillager`. The checked-in HTML, CSS and bundled scripts are ready to run; the build reproduces them from `src/` and the public presentation kit. Copy this directory into the instance's **Settings → Extensions → Open extensions folder**, or explicitly create a top-level development link. Discover, inspect the access declarations, then Enable. Your library is an application destination; Skills in this project is a left workspace destination. Detail viewers remain individually closable. hvir requires an open project as usual; the library need not be registered as a project.

Install and configure Skillager separately. The supported minimum version is **0.9.3**, with the current public `skillager.library-status.v1`, `skillager.list.v1` and `skillager.search.v1` contracts, including cursors and CLI-owned pre-limit grouping, installed filtering and ranking. Published 0.9.3 predates those new contracts while current supported source also identifies as 0.9.3. A matching version alone therefore does not prove support: the package checks each required public schema and refuses missing contracts with a setup explanation. There is no legacy search fallback or automatic installation. A current-source installation is a supported explicit setup.

In the Skillager installation's Settings controls, configure the exact installed executable separately for `library-cli` and `project-cli`, inspect its canonical path/configuration and approve native access. Optional declared environment overrides are `SKILLAGER_CATALOG_STATE_DIR`, `XDG_CACHE_HOME`, and `XDG_STATE_HOME`. Configure your personal library using Skillager's own public tools. Native executable approval grants no document reads. For `library`, inspect and grant the explicit canonical local library root; for `project`, separately grant the view's exact registered workspace scope. No SSH CLI is run: SSH project inventory/presence is explicitly unknown, while the personal library remains application-local and independently readable.

## Browse, search and read

Library browse follows opaque public list cursors in pages of 100; it does not truncate the library at 100. Search shows at most 50 metadata results per page and follows public search cursors. Skillager owns ranking and coverage: its current index includes names/descriptions and verified accepted-body terms up to its 50,000-character search bound; pending bodies are excluded. Guest browse/search does not prefetch instruction bodies. Include installed, Separate copies and Preferred agent are visible CLI-owned options applied before the result limit. Only an explicit local workspace root supplies `--installed-project`; absence or an SSH workspace never becomes local cwd or ambient project discovery. Project browse uses the CLI's metadata-only review without an action verb plus public exposure metadata. It reports observations without asserting exhaustive project discovery.

Keyboard arrows move selection without reading. Enter, Space or a row click opens that source's current instructions. Rendered and Source modes use the selected bytes; ordinary detail focus does not read again. Read current explicitly refreshes the selected source. Images are bounded relative assets confined to the selected document directory. Raw HTML and external links/resources remain inert. Markdown parsing reuses hvir’s document policy in one off-thread utility process; rendering output over 512 KiB falls back to complete Source bytes. Guest workers remain disabled. Main admits source paths up to 4096 UTF-8 bytes. The package also limits each exact path to 4096 bytes of JSON-encoded string content (4098 bytes including quotes), so source identity and bounded display metadata fit the complete 6144-byte JSON detail input. Unsupported identities are refused without truncation or substitution. File read time and SHA-256 describe current bytes independently of historical accepted tree hashes. Source details stay secondary to the instructions.

Refresh runs at a visible 30-second cadence and stops while hidden or closed. The one terminal-rail updater uses ordinary public observations; the platform connector owner controls common-source admission. Failed refresh preserves last-known rows with a freshness explanation. Empty library, no matches, unavailable contracts and unknown installed/project presence remain distinct. No management or curation preview is exposed.

Each source receipt has an absolute **five-minute** lifetime and a 2 MiB text/image limit, with 2048-byte pages. Requests are paced at 40 ms under the platform's 30-message/second cap; maximum text plus one maximum image fits that finite lifetime. Excess images remain explicitly unavailable; expiry or interruption never marks a partial body complete. Hiding interrupts reads; Read current explicitly resumes with a new current-file selection. Revoke, Disable, Reload, removal and Forget saved setup end source access while preserving external files. Agents and action/updater/restricted views cannot obtain instruction bodies through this package or the public source capabilities.

## Installed-CLI capacity probe

After configuring an existing current-contract CLI and its genuine library, set `HVIR_SKILLAGER_EVIDENCE_CLI`, `HVIR_SKILLAGER_EVIDENCE_CATALOG`, and `HVIR_SKILLAGER_EVIDENCE_LIBRARY` to their explicit local paths, then run `npm run probe:extension:skillager` from the checkout on an unlocked desktop. This opt-in native walkthrough uses ordinary Settings approval, public guest pagination/search and selected current reads. Its separate finite 15-minute limit supports a full 50-page, 5,000-skill library traversal; ordinary smoke deadlines stay unchanged. Each guest inspection has its own five-second bound and each page has a 60-second bound. The probe reports counts and phases without instruction contents. It does not install Skillager or change library acceptance.

For a focused selected-reader/visibility diagnosis against the same genuine library, append `-- --reader-diagnostic`. This explicitly skips the full traversal and does not replace its acceptance evidence.
